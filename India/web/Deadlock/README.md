कथा
इधर-उधर। फ़्रंटएंड से बैकएंड और फ़्लैग। छोटी बात, बस /admin से फ़्लैग ले लो।
इधर-उधर। फ़्रंटएंड से बैकएंड और फ़्लैग तैयार। सब सीधा, बस /admin से फ़्लैग ले लो।
चुनौती का सार
हमारे पास दो सर्वर हैं:
प्रॉक्सी (पोर्ट 5000) - उपयोगकर्ताओं से अनुरोध स्वीकार करता है
बैकएंड (पोर्ट 8081) - सीधे अनुपलब्ध, केवल प्रॉक्सी के माध्यम से
बैकएंड पर /admin एडमिन पैनल है, जिसके लिए X-Admin-Access: true हेडर ज़रूरी है।
लेकिन प्रॉक्सी सभी अनुरोधों से यह हेडर हटा देता है और X-Forwarded-For जोड़ता है।
सुरक्षा
अगर प्रॉक्सी को /admin पर सीधा अनुरोध भेजें हेडर के साथ:
GET /admin HTTP/1.1
X-Admin-Access: true
  प्रॉक्सी हेडर हटाएगा → बैकएंड फ़्लैग नहीं देगा।
भेद्यता
प्रॉक्सी में 0.CL Desync है — यह तब काम करता है जब Content-Length:\r\n (न्यूलाइन और स्पेस के साथ) दिखता है। इस मोड में प्रॉक्सी दूसरे अनुरोध को नहीं बदलता (हेडर नहीं हटाता और X-Forwarded-For नहीं जोड़ता)।
बायपास
पोर्ट 5000 पर एक अनुरोध भेजते हैं जिसके अंदर दो अनुरोध:
पहला (सामान्य) - प्रॉक्सी प्रोसेस करता है और हेडर हटाता है
दूसरा (smuggled) - प्रॉक्सी नहीं देखता, बैकएंड को वैसे ही भेजता है
बैकएंड दूसरा अनुरोध /admin पर X-Admin-Access: true हेडर के साथ और X-Forwarded-For के बिना प्राप्त करता है → फ़्लैग देता है।
अंतिम Payload
GET / HTTP/1.1
Host: admin.challenge.local:5000
Content-Length:
 67
Connection: keep-alive

GET /admin HTTP/1.1
Host: localhost:8081
X-Admin-Access: true
