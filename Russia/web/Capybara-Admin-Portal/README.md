## Описание задания

Админ капибар харнит какой-то важный серкрет. Нам удалось узнать только ID его аккаунта - 239716013. Достаньте этот секрет как можно скорее.

## Шаг 1: Сбор информации и User Enumeration

Открываем главную страницу. Видим форму входа. Попробуем ввести случайные данные.
Ввод test:test -> Ответ: 404 Пользователь не найден в вольере.
Ввод admin:admin -> Ответ: 404 Пользователь не найден в вольере.

Это классическая уязвимость User Enumeration. Сервер сообщает нам, существует ли пользователь. Начинаем перебор по списку rockyou.txt. Довольно быстро находим имя angel.
Ввод angel:test -> Ответ: 401 Неверный пароль для капибары.

Пользователь angel существует!

## Шаг 2: Brute-force пароля

Теперь перебираем пароли для пользователя angel по тому же списку rockyou.txt. Находим верный пароль: princess.

## Шаг 3: Обход 2FA (JWT Leak)

После ввода верных данных нас перекидывает на страницу /2fa. Здесь просят ввести 6-значный код. Однако, если заглянуть в Network (вкладка в инструментах разработчика) на запрос /login, мы увидим, что сервер вернул JSON:
{
  "token": "eyJhbGciOiJIUzI1NiI...",
  "user_id": "679202372644",
  "redirect": "/2fa"
}
Сервер выдал нам JWT токен еще до прохождения 2FA. Это ошибка логики (2FA Bypass). Этот токен уже можно использовать для авторизации в API.

## Шаг 4: Анализ API и Path Traversal

На странице 2FA открываем консоль (F12). Видим логи: [API] Внутренний эндпоинт управления аккаунтами: POST /admin/account/679202372644

Если мы попробуем сделать запрос к этому эндпоинту с нашим токеном:

getAccountData('679202372644')
Мы получим ответ, что у нас нет прав на флаг, и флаг лежит в 239716013.

Если попробуем напрямую:

getAccountData('239716013')
Получим 403 Ошибка доступа. Сервер проверяет, что ID в URL совпадает с ID в нашем токене.

Но ручка API использует path параметр, который не фильтрует символы перехода по директориям. Мы можем использовать Path Traversal, чтобы в пути присутствовал и наш ID (для прохождения проверки), и целевой ID.

## Шаг 5: Получение флага

Формируем запрос, где путь будет выглядеть так: /admin/account/679202372644/../239716013. Чтобы сервер не "схлопнул" точки до обработки в коде, используем URL-кодирование для слешей (%2f).

Итоговый запрос в консоли браузера:

fetch('/admin/account/679202372644%2f..%2f239716013', {
    method: 'POST',
    headers: {
        'Authorization': 'Bearer ' + localStorage.getItem('jwt'),
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({ action: 'fetch_secure_data' })
}).then(res => res.json()).then(console.log);

Результат: {"status": "success", "owner": "Главная Капибара", "data": "KubSTU{c4pyb4r4_p4th_tr4v3rs4l_m4st3r}"}
